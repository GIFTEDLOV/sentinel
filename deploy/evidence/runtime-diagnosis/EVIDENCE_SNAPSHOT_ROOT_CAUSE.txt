Exact count-drop location
-------------------------
The count did not drop while reading the incident, reading the two evidence
records, computing freshness, or computing distinct source domains. The deployed
assessment passed a metadata list into semantic judgment, and _judge_evidence
then called _authenticate_one again for each item inside the leader and
validator nondeterministic callbacks. That second live re-authentication was
the count-drop boundary: the hosted receipt reports leader authenticated/source
counts 0/0 and reason "Evidence could not be safely authenticated", while the
same assessment finalized with successful nondeterministic execution and LLM
activity.

This is a duplicate live-authentication / missing frozen-snapshot payload bug,
not a storage decoding failure. The receipt also shows the prior storage-boundary
fix had already allowed the assessment to reach nondeterminism.

Fix applied locally
-------------------
The local source now authenticates evidence once during bind_evidence, stores
the authenticated status, canonical facts, and normalized flags, then builds a
plain dict/list assessment_context before run_nondet. It computes bound_count,
authenticated_count, fresh_count, and distinct_count deterministically and
rejects failed quorum before nondeterminism. Both leader and validator consume
the same context; semantic callbacks perform no storage reads, contract calls,
or web fetches.

The same context architecture is used for recovery assessment. No chain write,
deployment, incident creation, outflow, or advisory publication was performed
while applying this fix.
